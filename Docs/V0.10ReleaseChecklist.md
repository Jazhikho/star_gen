# StarGen v0.10 Release Checklist

This checklist is for cutting the approved `0.10` release builds that can be reviewed locally and then posted to itch.

## Supported Release Shape

- User-facing release label: `0.10`
- Internal checkpoint source of truth: `project.godot`, `VERSION.md`, `export_presets.cfg`, and `src/app/shared/UserFacingVersionHelper.cs`
- Public demo scope: generation and viewing only
- Export-enabled scope: generation, viewing, and save/load authoring flows
- Primary itch targets for this repo: `windows` and `linux`
- `web` should stay unpublished unless a local export succeeds and passes the live acceptance checklist

## One-Time Prerequisites

- Godot `.NET` `4.6.x` installed, with the console executable path known
- Matching Godot export templates installed for each target preset you intend to ship
- `.NET SDK` installed and able to build `StarGen.sln`
- Optional: [butler](https://itch.io/docs/butler/) installed and authenticated for itch uploads

## Pre-Release Gate

1. Confirm the version surfaces are synchronized:
   - internal checkpoint surfaces: `project.godot`, `VERSION.md`, `src/app/shared/UserFacingVersionHelper.cs`
   - release-target surfaces: `export_presets.cfg`, scene-owned user-facing version placeholders, release notes, `README.md`
2. Confirm the active edition target matches the intended scope:
   - public demo channel: no usable save or load controls in Galaxy, System, or Object viewers
   - export-enabled channel: save/load affordances are present only where the app actually supports them
   - no app-facing Concept Atlas route
3. Run the normal verification gate:
   - `dotnet build StarGen.sln`
   - `godot-mono.exe --path . --headless --script res://Tests/RunTestsHeadless.gd`
4. Review the current [live acceptance checklist](./V0.10AcceptanceChecklist.md) and execute it on exported artifacts, not just in-editor runs.

## Build Procedure

### Preferred: scripted build

Run:

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\CreateReleaseBuild.ps1 -GodotExe "C:\Path\To\Godot_v4.6-stable_mono_win64_console.exe"
```

That default command cuts the public demo channel with visible version `0.10`.

To cut the export/save-enabled channel:

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\CreateReleaseBuild.ps1 -GodotExe "C:\Path\To\Godot_v4.6-stable_mono_win64_console.exe" -Edition export
```

For the approved `0.10` release candidate, pass the release target explicitly if the project file has moved ahead:

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\CreateReleaseBuild.ps1 -GodotExe "C:\Path\To\Godot_v4.6-stable_mono_win64_console.exe" -Version "0.10.0.0"
```

Default behavior:

- runs `dotnet build StarGen.sln`
- runs the full headless harness
- temporarily stamps the requested edition channel (`demo` or `export`) for the build and then restores the repo file
- exports `Windows Desktop` and `Linux`
- excludes non-runtime repo folders such as `Tests/`, `Docs/`, `Sources/`, and `Concepts/`
- writes outputs under `release/<internal-version>/<artifact-label>/`
- zips each exported platform folder
- prints suggested itch `butler push` commands

Artifact labels:

- public demo channel: `0.10`
- export-enabled channel: `0.10-export`

Useful variants:

```powershell
# Windows only
powershell -ExecutionPolicy Bypass -File .\scripts\CreateReleaseBuild.ps1 -GodotExe "C:\Path\To\Godot_v4.6-stable_mono_win64_console.exe" -Presets "Windows Desktop"

# Skip tests only if you already ran them in the same clean commit state
powershell -ExecutionPolicy Bypass -File .\scripts\CreateReleaseBuild.ps1 -GodotExe "C:\Path\To\Godot_v4.6-stable_mono_win64_console.exe" -SkipTests
```

### Manual editor export

If you prefer the Godot editor:

1. Open `project.godot` in Godot `4.6.x .NET`.
2. Open `Project -> Export`.
3. Set `application/config/release_channel` to `demo` for the public build or `export` for the export-enabled build.
4. Use the `Windows Desktop` and `Linux` presets.
5. Export into a versioned local folder such as:
   - `release/<internal-version>/0.10/windows/StarGen.exe`
   - `release/<internal-version>/0.10/linux/stargen.x86_64`
   - `release/<internal-version>/0.10-export/windows/StarGen.exe` for export-enabled Windows builds
6. Restore `application/config/release_channel` after manual export if you changed it locally.
7. Zip each platform folder after export.

## Artifact Review

For each shipped target:

1. Launch the exported build outside the repo.
2. Run the full [live acceptance checklist](./V0.10AcceptanceChecklist.md).
3. Confirm the build does not depend on repo-relative files.
4. Confirm the visible version label reads `0.10`.
5. Confirm the build reflects that channel's scope:
   - public demo channel: no usable save/load affordances in shipped viewers
   - export-enabled channel: save/load affordances work only in the supported viewer paths
6. Confirm generation studios and viewers remain the primary supported path.

## Itch Publishing

### Recommended channel layout

- `windows`
- `linux`
- optional export-enabled paid channels if the release uses a pricing split

Do not publish a `web` channel unless the local web export succeeds and passes acceptance.

### With butler

After building and reviewing artifacts, push the exported folders or zips. Folder upload is preferred for native channels.

Example:

```powershell
butler push "release\<internal-version>\<artifact-label>\windows" your-itch-user/stargen:windows
butler push "release\<internal-version>\<artifact-label>\linux" your-itch-user/stargen:linux
```

### Without butler

1. Open your itch project dashboard.
2. Create or update native uploads for `Windows` and `Linux`.
3. Upload the zip produced under `release/<internal-version>/<artifact-label>/`.
4. Paste release notes derived from `VERSION.md` plus any short user-facing highlights.

## Release Notes Minimum

At minimum, the release notes for `0.10` should state:

- The visible release label is `0.10`.
- Galaxy, System, Object, and Station studios are the supported entry points.
- Station Studio now uses the single-station generation workflow with construction and station-population readouts.
- Scientific assumptions and compatibility overrides are partitioned clearly.
- The public build keeps save/load disabled, while export-enabled builds enable them in the supported viewer paths.
- Any known caveats, especially if a target such as `web` was intentionally not shipped.

## Post-Upload Spot Check

After posting to itch:

1. Download the uploaded artifact from itch.
2. Launch it from the downloaded location.
3. Re-run a shortened smoke pass from the [acceptance checklist](./V0.10AcceptanceChecklist.md):
   - startup and version label
   - main menu
   - Galaxy Studio -> Galaxy Viewer
   - System Studio -> System Viewer
   - Object Studio -> Object Viewer
   - Station Studio -> Generate Station
4. Confirm the itch page metadata, screenshots, and downloadable channels match the actual shipped targets.
