# StarGen v1.0 Checklist

This is the concrete checklist for moving from the current late-`0.9` state to a defensible `1.0`.

## 1. Scope Lock

- [ ] Mainline and export-branch responsibilities are fully stable and documented.
- [ ] No parked prototype or concept residue remains on the shipped runtime path.
- [ ] User-facing docs describe only the workflows the shipped build actually supports.

## 2. Engine-First UI Completion

- [ ] Fixed viewer and studio structure is scene-authored in `.tscn`.
- [ ] Scripts handle behavior, state transitions, and dynamic data only.
- [ ] Remaining runtime-created UI is limited to truly variable-length data and is documented as such.

## 3. Scientific Pipeline Closure

- [ ] Every retained science-facing parameter has an explicit downstream effect.
- [ ] Major output families depend on more than one upstream parameter where scientifically justified.
- [ ] Galaxy, stellar, planetary, habitable-zone, life, and sentient-world assumptions are documented and test-covered.
- [ ] Legacy alias fields remain compatibility-only and are not presented as active science controls.

## 4. Sentient-World And Compatibility Audit

- [ ] Sentient-world baseline fields are stable enough to map into supported RPG compatibility outputs.
- [ ] Government, law, technology, and settlement outputs receive explicit human audit before release.
- [ ] Compatibility adapters stay clean-room and document what is baseline realism versus ruleset mapping.

## 5. Release Hardening

- [ ] Export presets, build scripts, and version surfaces stay synchronized.
- [ ] Release artifacts can be generated repeatably from a documented procedure.
- [ ] Live acceptance checklist passes on shipped artifacts for every published platform.
- [ ] Known issues and unsupported channels are called out before release.

## 6. Documentation And Provenance

- [ ] `README.md`, `VERSION.md`, `Docs/ProjectStructure.md`, and release docs match the current shipped build.
- [ ] Significant AI-assisted work is logged in `AI-Provenance-Log.md`.
- [ ] Scientific, realism, and sentient-world claims have explicit reviewed-source anchors and human signoff.

## 7. Final `1.0` Gate

- [ ] Full automated verification passes in the release commit state.
- [ ] Manual acceptance passes on the exported builds.
- [ ] Human review signs off on realism, compatibility boundaries, licensing boundaries, and release notes.
- [ ] Release build versioning is promoted intentionally rather than drifting out of the internal checkpoint line.
