# StarGen v0.10 Live Acceptance Checklist

Run this against exported release artifacts, not only in-editor runs. Mark whether you are reviewing the public `demo` channel or the export-enabled channel before you start.

## Startup And Shell

- [ ] Launch starts without missing-resource dialogs or immediate crashes.
- [ ] Splash video appears unless `Skip Intro` was previously enabled.
- [ ] Clicking or pressing a key skips the splash correctly.
- [ ] Main menu appears after splash without hanging on a black screen.
- [ ] Visible version label reads `0.10`.
- [ ] Main menu utility panels open correctly: `Help`, `Credits`, `Sources`, `Release Notes`, `Options`.

## Main Menu Options

- [ ] `Fullscreen` toggle applies and persists after relaunch.
- [ ] `Show studio seeds` toggle applies and persists after relaunch.
- [ ] `Skip intro` toggle applies and persists after relaunch.
- [ ] Windowed resolution changes apply correctly when not fullscreen.

## Galaxy Studio To Galaxy Viewer

- [ ] `Open Galaxy Studio` works from the main menu.
- [ ] Galaxy Studio loads with science assumptions separated from override/readout controls.
- [ ] Generate a galaxy successfully from the studio.
- [ ] Galaxy Viewer opens and shows top bar, overview panel, and controls panel correctly.
- [ ] Expanding and collapsing the `Controls` box keeps the box anchored correctly.
- [ ] Galaxy Viewer controls text matches the active camera mode.
- [ ] Selecting a star updates `System Preview`.
- [ ] `Open System` from Galaxy Viewer opens System Viewer successfully.
- [ ] Returning from System Viewer restores Galaxy Viewer without losing the active generated context.

## System Studio To System Viewer

- [ ] `Open System Studio` works from the main menu.
- [ ] System Studio loads with stellar, planetary, life, overrides, and readout controls in the expected sections.
- [ ] Generate a system successfully from the studio.
- [ ] System Viewer opens with the correct overview, orbit rendering, and control help.
- [ ] System Viewer `Controls` expand and collapse from the scene-authored bottom-right position without jumping.
- [ ] Clicking a body selects it and updates the inspector.
- [ ] Opening an object from the system view launches Object Viewer successfully.
- [ ] Returning from Object Viewer restores System Viewer correctly.

## Object Studio To Object Viewer

- [ ] `Open Object Studio` works from the main menu.
- [ ] Object Studio shows object-type-specific controls without leaking unrelated sections.
- [ ] Generate at least one planet and one non-planet object successfully.
- [ ] Object Viewer opens with the expected body render, inspector, and controls.
- [ ] Object Viewer `Controls` expand and collapse from the correct scene-owned position.
- [ ] Population fields stay hidden on uninhabited worlds.
- [ ] Population fields appear on inhabited worlds and show the sentient-world baseline fields.
- [ ] Public demo channel keeps object save/load controls hidden.
- [ ] Export-enabled channel shows object save/load controls and opens the expected file dialogs.

## Station Studio

- [ ] `Open Station Studio` works from the main menu.
- [ ] Station Studio does not generate a station before `Generate Station` is pressed.
- [ ] Station inputs support random-or-defined class, type, context, purpose, and density choices.
- [ ] RPG override controls are clearly separated from RPG-agnostic station inputs.
- [ ] Generating a station updates the single station report without errors.
- [ ] Construction, classification, and station-population readouts appear for detailed generations.
- [ ] Returning to the main menu works correctly.

## Viewer Scope And Mainline Constraints

- [ ] Public demo channel: Galaxy, System, and Object viewers do not expose usable save or load actions.
- [ ] Export-enabled channel: System and Object viewers expose the intended save/load actions, and those actions function.
- [ ] No Concept Atlas or other MythicWorldGen-facing route appears in the shipped UI.
- [ ] Viewer scenes look scene-authored and not obviously rebuilt from script at runtime.

## Release Packaging Checks

- [ ] The build runs from outside the repo tree.
- [ ] The build folder contains the expected executable and data payload.
- [ ] Zipped artifacts extract and launch successfully.
- [ ] The itch-ready artifact names match the intended release version, edition label, and platform.

## Final Publish Decision

- [ ] All checked platforms passed this acceptance run.
- [ ] Any known issues are documented in the release notes.
- [ ] Itch channels match only the platforms that actually passed acceptance.
