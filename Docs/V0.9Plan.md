# StarGen v0.9 Implementation Plan

This plan is based on a direct review of the current codebase and is scoped to the v0.9 direction:

1. Scene-first UI (`.tscn`) with minimal code-built controls.
2. Scientific realism alignment end-to-end with `Docs/galactic_formation.md`.
3. Scope split from concept-heavy systems moving to MythicWorldGen.
4. Main branch as generation-only; save/load/export moved to export branch.
5. Version suffix policy: main `d`, export branch `e`.

---

## Current Gaps Identified

### 1) UI still heavily built in C# in key screens

The following files still build substantial UI at runtime (labels/rows/buttons/sections), which conflicts with the v0.9 `.tscn`-first requirement:

- `src/app/galaxy_viewer/GalaxyInspectorPanel.cs` (`BuildUi`, config rows, colonization controls, issue labels).
- `src/app/system_viewer/SystemInspectorPanel.cs` (`BuildUi`, section construction and row rendering).
- `src/app/concepts/ConceptAtlasScreen.cs` (`RenderMetrics`, `RenderSections` instantiate controls each refresh).
- `src/app/viewer/InspectorPanel.cs` (dynamic section/row creation).
- `src/app/viewer/EditDialog.cs` (large dynamic form construction in code).
- `src/app/ObjectGenerationScreen.cs` and `src/app/ObjectGenerationScreen.EnhancedUi.cs` (runtime notes/issue controls).
- `src/app/SystemGenerationScreen.cs` and `src/app/GalaxyGenerationScreen.cs` (runtime issue label instantiation).

Status: partially migrated (many screens already have `.tscn` files), but not complete.

### 2) Save/load/export is still present throughout mainline flows

Mainline currently exposes persistence directly in navigation, viewers, and services:

- `src/app/MainApp.Navigation.cs` (load dialogs and file-open handlers from menu/studios).
- `src/app/system_viewer/SystemViewerSaveLoad.cs` (system save/load dialogs + file handlers).
- `src/app/galaxy_viewer/GalaxyViewerSaveLoad.cs` (viewer saved-state + file flows).
- `src/app/viewer/ObjectViewer.SaveLoad.cs` (object save/load UI and path handlers).
- `src/services/persistence/SystemPersistence.cs`
- `src/services/persistence/GalaxyPersistence.cs`
- `src/services/persistence/CelestialPersistence.cs`
- `src/services/persistence/SaveData.cs` and related persistence DTOs.

Status: directly conflicts with v0.9 "main branch generation-only" requirement.

### 3) Scientific realism framework exists but is not wired end-to-end

Key realism gap found:

- `src/domain/generation/GenerationRealismProfile.cs` explicitly states the profile is "Data model only — no generator currently reads this profile."

Related realism tuning exists but is currently shallow/high-level:

- `src/domain/generation/GenerationUseCaseSettings.cs` (ruleset + permissiveness sliders).
- `src/domain/galaxy/GalaxyConfig.cs` (morphology and structural controls).
- `src/domain/bootstrap/CSharpGenerationRealismProfileBridge.cs` (bridge payload only).

Status: realism intent is present in UI/data structures, but pipeline coupling to generator behavior is incomplete versus `Docs/galactic_formation.md`.

### 4) Concept-heavy surfaces still in StarGen mainline

MythicWorldGen-bound concept surfaces are still in active app paths:

- Main menu still routes to Concept Atlas: `src/app/MainMenuScreen.cs`.
- Runtime concept screen and services remain active: `src/app/concepts/ConceptAtlasScreen.cs`, `src/services/concepts/ConceptContextBuilder.cs`, and related concept domain modules.

Status: conflicts with scope split and handoff plan.

### 5) Version suffix branch policy is not yet implemented

Current user-facing version helper reads static labels but has no branch-suffix policy:

- `src/app/shared/UserFacingVersionHelper.cs`

Status: `d`/`e` suffix behavior is not enforced in code or release process.

## v0.9 Workstreams and Specific Adjustments

## WS1 - Complete Scene-First UI Migration

Goal: all static/presentational UI lives in `.tscn`; scripts bind behavior only.

Actions:

- For each runtime-built panel in `GalaxyInspectorPanel`, `SystemInspectorPanel`, `InspectorPanel`, and `EditDialog`:
  - Create explicit node trees in corresponding `.tscn`.
  - Replace control instantiation (`new Label`, `new Button`, `new HBoxContainer`, etc.) with cached node references.
  - Keep dynamic text/value updates, but avoid creating/destroying structural controls at runtime unless content is truly data-driven and unbounded.
- Move validation/issue UI shells into scene nodes for:
  - `GalaxyGenerationScreen`, `SystemGenerationScreen`, `ObjectGenerationScreen`.
- Keep a strict exception list for runtime-instantiated controls (only for variable-length generated content, with documented reason).

Definition of done:

- No structural UI bootstrap methods (`BuildUi`) for fixed inspector/generation layouts.
- Scripts primarily perform: signal wiring, value updates, show/hide logic, and data binding.
- Manual QA confirms visual parity after migration.

## WS2 - Realism Pipeline Integration (`galactic_formation.md` alignment)

Goal: realism settings influence generation outputs at each tier, not just labels.

Actions:

- Introduce a realism parameter contract in domain generation:
  - Add tiered realism/tunable structures for galaxy, stellar, planetary, and habitability assumptions.
  - Map contested parameters from `Docs/galactic_formation.md` to explicit config fields (defaults + ranges).
- Wire `GenerationRealismProfile` into generator entry points:
  - Galaxy generation path.
  - System generation path.
  - Object generation presets/spec pathways.
- Ensure provenance captures realism profile + tunables used for each generation output.
- Add deterministic tests validating:
  - same seed + same realism profile => same outputs,
  - changed realism inputs => expected constrained distribution changes (not random drift).

Initial target files:

- `src/domain/generation/GenerationRealismProfile.cs`
- `src/domain/generation/GenerationUseCaseSettings.cs`
- `src/domain/galaxy/GalaxyConfig.cs`
- generator entry/use-case files in `src/domain/generation/` and system/galaxy generation call sites in `src/app/`.

Definition of done:

- No realism profile remains "data-model only."
- Realism options are active in generation, documented, and test-covered.

## WS3 - Remove MythicWorldGen-bound concepts from mainline scope

Goal: StarGen mainline retains generation/viewing core only.

Actions:

- Remove Concept Atlas entry point from menu and navigation:
  - `src/app/MainMenuScreen.cs`
  - `src/app/MainApp.Navigation.cs`
- Deactivate concept-tool UI from standard scene flow and release build path.
- Keep handoff inventory in docs (`Concepts/Additions.md` + roadmap references), but stop shipping concept tool runtime in main release.

Definition of done:

- Mainline app flow has no concept-atlas route.
- Concept-heavy modules are either removed from mainline, compile-gated, or isolated for migration branch.

## WS4 - Mainline Generation-Only Split (remove save/load/export)

Goal: main branch has no save/load/export features; export branch carries them.

Actions (main branch):

- Remove or disable save/load/export UI affordances and handlers in:
  - `MainApp.Navigation`
  - `SystemViewerSaveLoad`
  - `GalaxyViewerSaveLoad`
  - `ObjectViewer.SaveLoad`
- Remove persistence services from mainline runtime dependencies:
  - `SystemPersistence`, `GalaxyPersistence`, `CelestialPersistence`, `SaveData`, and related DTO/services.
- Keep in-memory/session-only state for current runtime navigation.

Actions (export branch):

- Reintroduce persistence + export paths.
- Add MythicWorldGen import/export compatibility contract and artifact validation tests.
- Keep branch-specific release packaging so export features do not ship in standard StarGen release.

Definition of done:

- Mainline contains no end-user save/load/export path.
- Export branch is the sole location for persistence/export capability.

## WS5 - Version Label Branch Suffix Policy

Goal: enforce `d` for mainline and `e` for export builds.

Actions:

- Extend version resolution in `src/app/shared/UserFacingVersionHelper.cs`:
  - derive display suffix from branch/build channel metadata (not manual ad hoc string edits).
- Update `project.godot`/version metadata process so branch suffix is consistently applied in UI and build outputs.
- Add a lightweight version-format validation test to prevent wrong suffix in CI/build scripts.

Definition of done:

- Mainline builds always show `...d`.
- Export builds always show `...e`.

## Execution Order (Recommended)

1. **Scope lock + menu pruning** (WS3 first) to stop further concept-surface drift.
2. **Persistence split** (WS4) to establish branch architecture and avoid rework.
3. **UI migration** (WS1) after branch responsibilities are clear.
4. **Realism pipeline integration** (WS2) as primary domain milestone for v0.9 quality.
5. **Version suffix automation** (WS5) before release candidate freeze.

---

## Test and Verification Gates for v0.9

- Determinism tests pass for generator tiers touched by realism integration.
- Regression baselines updated only where realism changes intentionally alter outputs.
- UI smoke tests:
  - main menu -> galaxy/system/object generation paths work with no save/load/export UI in mainline,
  - inspector and generation screens render correctly from `.tscn` with no missing-node errors.
- Branch-policy checks:
  - mainline build label ends with `d`,
  - export build label ends with `e`,
  - export-only features are absent from standard release build artifacts.

---

## Risks and Mitigations

- **Risk:** UI migration introduces missing-node regressions.
  - **Mitigation:** migrate screen-by-screen with temporary compatibility fallbacks and scene validation tests.
- **Risk:** realism wiring changes output distributions significantly.
  - **Mitigation:** formalize target ranges from `Docs/galactic_formation.md` and compare against deterministic benchmark fixtures.
- **Risk:** branch split creates merge friction.
  - **Mitigation:** define clear ownership: mainline (generation/view only) vs export branch (persistence/export), and avoid dual-editing persistence code in mainline.
